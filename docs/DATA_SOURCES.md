# Data Sources

## Implemented source: Nextbike GBFS

The collector uses the Nextbike Polish GBFS discovery URL:

`https://gbfs.nextbike.net/maps/gbfs/v2/nextbike_pl/gbfs.json`

It reads `data.pl.feeds` and discovers URLs by feed name. The six required
feeds are:

| Feed | Source grain | Main use |
| --- | --- | --- |
| `station_information` | One station per feed observation. | Station attributes in Silver and snapshot dimension in Gold. |
| `station_status` | One station state per feed observation. | Central station-availability fact and system bike totals. |
| `free_bike_status` | One publicly listed bike state per feed observation. | Visible-bike snapshot fact; not trip evidence. |
| `vehicle_types` | One vehicle type per feed observation. | Vehicle dimension and e-bike classification. |
| `system_pricing_plans` | One plan per feed observation, with nested tiers. | Pricing dimension and normalized tier table. |
| `system_regions` | One region per feed observation. | Region dimension. |

The discovery endpoint is under the GBFS v2 path, but the client validates
each returned envelope's `last_updated`, `ttl`, `version`, and `data` types
without hard-coding the returned version string. Unknown envelope fields and
nested data are retained in Raw.

`last_updated` is provider metadata. `observed_at` is generated by the
application at retrieval time in UTC and identifies the collected state.
Feeds are fetched sequentially; their observation timestamps are not
guaranteed to be identical. See [GBFS ingestion](GBFS_INGESTION.md).

## Wrocław Open Data

Historical bike-rental data is a possible future authoritative source for
trip analysis, but there is no Wrocław Open Data ingestion, trip table, or
trip analysis in the current pipeline. Public dataset freshness and endpoint
availability must be verified before designing an implementation. No trips
are inferred from GBFS snapshots.

## Source interpretation

- GBFS is periodic operational state, not an event stream.
- A bike missing from a later `free_bike_status` response is not proof of a
  rental or trip.
- Source payloads are retained before typed transformation.
- Local fixture or test data must not be described as a complete authoritative
  history of Wrocław rides.
