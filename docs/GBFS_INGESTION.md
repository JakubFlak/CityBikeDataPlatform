# GBFS Ingestion

## Discovery

The client retrieves the Nextbike discovery document from:

`https://gbfs.nextbike.net/maps/gbfs/v2/nextbike_pl/gbfs.json`

It selects the `data.pl.feeds` section and discovers feeds by their `name`.
Individual feed URLs are never constructed from filenames. The ingestion layer
currently requires exactly these six feeds:

- `vehicle_types`
- `station_information`
- `station_status`
- `free_bike_status`
- `system_regions`
- `system_pricing_plans`

`system_information` and `system_hours` are intentionally excluded.

## Validation and timestamps

Every feed must contain the GBFS envelope fields `last_updated`, `ttl`,
`version`, and `data`, with integer, integer, string, and object types
respectively. Unknown fields are retained in the raw source payload.

`last_updated` is the provider's timestamp and is preserved unchanged.
`observed_at` is generated by this application at retrieval time. It is a
timezone-aware UTC timestamp in application code and is persisted as an
ISO-8601 UTC string with an explicit offset.

## Raw storage

The standalone smoke command is:

```text
python scripts/gbfs_live_smoke.py
```

It writes one Parquet file per feed observation under:

```text
data/raw/<feed_name>/observed_at=<UTC timestamp>/snapshot.parquet
```

Each file has one row for one feed observation. It contains feed identity,
source URL, `observed_at`, the envelope metadata, `data_json`, and
`source_payload_json`. The two JSON columns preserve nested source structures
without analytical flattening. Runtime raw data is ignored by Git.

This layer does not filter to Wroclaw, derive trips, or create analytical
tables. Those decisions belong to later transformation work.

## Raw quality checks

Run the inspection command after ingestion:

```text
python scripts/inspect_raw_quality.py
```

The reusable checks in `bike_data.raw_quality` inspect each Parquet file and
report fatal errors separately from warnings. They verify the physical schema,
one-row snapshot grain, required metadata, timestamp compatibility, JSON
validity, expected non-empty feed collections, feed-specific identifiers,
canonical `data_json` versus `source_payload_json.data` equivalence, and
metadata consistency. `data_json` is the canonical downstream payload;
`source_payload_json` is retained only as the raw/audit representation.

The current six-file inspection passes with zero errors and zero warnings.
Observed collection sizes are 9 vehicle types, 273 station-information
records, 273 station-status records, 2 pricing plans, 6 regions, and 2,869
free bikes.
